# SmartStir Lab V1.3.2 — CSV 实验运行记录

## 实现方式

- **不需要 RTC/DS3231 或 Micro SD 卡**：只要 ESP32 能通过 Wi-Fi / TLS MQTT 把状态发送到 EMQX，Railway V1.3 网关会在 PostgreSQL 中记录实验状态。
- ESP32 当前固件 `REPORT_INTERVAL_MS=3000`，一般约每 3 秒上报一次状态。以服务器实际收到的时间为准，网络延迟会影响采样时间。
- 电机第一次上报 `motor_enabled=true` 时，自动创建实验运行记录（run）。
- 运行期间，每条**非保留** MQTT 状态消息保存一次采样（状态、PWM、可选 RPM、fault、uptime）。
- 上报停止时，写入最后一个 STOP 样本，并结束此次 run。若状态消息间隔超过 15 秒，下次收到状态或用户查询历史时，会将上一条记录标记为 `signal_lost`。
- **断网期间云端不能采样**，数据不回补。若需离线数据不丢失，仍需设计本地缓存/存储方案。
- 未装霍尔传感器时 `actual_rpm` 为空，不可拿 PWM 百分比代替 RPM。

## CSV 格式

每次运行一个 CSV，默认文件名：`SmartStir-stirrer-001-<run-id>.csv`。

字段顺序：

```csv
timestamp_utc,device_id,motor_enabled,pwm_percent,actual_rpm,fault,uptime_ms
"2026-11-14T12:00:00.000Z","stirrer-001","true","30",,,"3000"
"2026-11-14T12:00:03.000Z","stirrer-001","true","45",,,"6000"
"2026-11-14T12:00:06.000Z","stirrer-001","false","0",,,"9000"
```

以上为**格式示例，不是实测数据**。CSV 使用 UTF-8 BOM + CRLF，WPS/Excel 一般可正确识别。时间采用 ISO8601 UTC；APP 列表转为手机当地时区显示。设备 fault 文本会进行 CSV 特殊字符和公式注入转义。

## APP 使用方法

1. 使用 V1.3.2 Preview 登录，进入自己的实验室，点击已绑定 ESP32。
2. 控制台执行电机运行；APP 可以不一直打开，记录由**云端**完成。
3. 点击底部 **实验记录 / Experiments / 実験記録**，查看最近 50 次运行。
4. 点击某次运行的 **导出 CSV**，通过 Android 分享面板保存到文件或发送到自己的电脑。
5. CSV 权限与实验室设备权限绑定，未获授权者不能读取或下载。

## API 和存储

- `GET /api/v1/devices/:device_id/runs`：最近 50 次运行，需 Bearer token + 设备所属实验室权限。
- `GET /api/v1/devices/:device_id/runs/:run_id.csv`：导出单次运行 CSV，最多 50,000 条样本，超出返回 HTTP 413（不静默截断）。
- PostgreSQL 表：`experiment_runs`、`experiment_samples`。脚本使用 `CREATE TABLE IF NOT EXISTS` 迁移，原有表不清空。
- 实验记录**没有自动清理策略**，500 MB 的数据库卷需要监测剩余空间和备份。大量长期运行需要后续增加保留期限、归档和索引优化。
- 部署前的历史数据无法自动补录，只有新版网关部署后实际接收到的非保留状态才能形成新记录。

## 安全验收

自动测试在一次性 PostgreSQL 数据库中插入模拟数据，验证 CSV 编码、字段、公式注入转义以及实验室权限。生产环境仍需现场有人监护、断开动力电源进行通讯测试，不应通过自动测试或远程检查启动实际电机。
